# Execution capability contract

This table is the authoritative inventory for supported non-web execution behavior. “Supported” means the named production or library entry point consumes the setting and the named contract exercises that entry point. `attractor-web` is outside this contract.

| Surface | Status | Production consumer | End-to-end contract |
|---|---|---|---|
| `max_retries` / node `timeout` | Supported. A retry count of N permits N + 1 attempts during one node visit; every attempt consumes one `max_steps` unit. Timed-out built-in subprocess handlers terminate their process group even when the executor's outer deadline cancels the handler future. | `ExecutionPlan` compiles `NodeInvocationPolicy`; `PipelineExecutor::invoke_node` enforces retries and deadlines for every handler, including exit handlers; `ProcessGroupGuard` owns cancellation cleanup for subprocess handlers. | `node_max_retries_reinvokes_handler_until_success`, `exit_handlers_use_the_same_retry_boundary`, `retry_attempts_consume_the_global_step_limit`, `canonical_tool_timeout_terminates_descendant_processes` |
| Goal-gate retry targets | Supported for non-terminal targets. Node and graph `retry_target` / `fallback_retry_target` values that resolve to an exit node are rejected because revisiting an exit cannot change a failed gate. | `validate_plan_structure` blocks terminal retry targets before execution; ordinary retry traversal is bounded by handler-attempt `max_steps` accounting. | `terminal_retry_targets_are_blocking_errors`, `exit_goal_gate_retry_target_fails_before_execution` |
| Handler-attempt checkpoint state | Supported. Begun attempts are durable; delivery is not rolled back on resume. | `PipelineCheckpoint::{total_handler_attempts,active_node_id,active_node_attempts}` and `PipelineExecutor::invoke_node` | `retry_attempts_are_checkpointed_before_handler_invocation`, `backward_compatibility_without_session_id` |
| `EventEmitter` / `PipelineEvent` | Supported as best-effort observation, not durable workflow state. A missing or lagging subscriber cannot fail a run. | `PipelineExecutor::with_event_emitter`, `PipelineExecutor::invoke_node`, and committed routing/context/checkpoint operations | `executor_emits_pipeline_stage_context_and_edge_lifecycle`, `executor_emits_exactly_one_pipeline_failure_for_runtime_errors`, `absent_or_lagging_event_subscribers_cannot_change_execution` |
| DOT prompt/model transforms | Supported before node/provider resolution. | `ExecutionPlan::compile_with_policy` calls `apply_transforms` | `aliases_styles_and_prompt_transforms_precede_compilation` |
| `SessionConfig.model` | Supported. | `AgentSession::build_request` | `session_model_and_system_prompt_reach_the_provider_request` |
| `SessionConfig.system_prompt` | Supported. | `AgentSession::build_request` | `session_model_and_system_prompt_reach_the_provider_request` |
| `SessionConfig.max_turns` | Supported. | `AgentSession::process_single_input` | `turn_limit_enforcement` |
| `SessionConfig.max_tool_rounds` | Supported. | `AgentSession::process_single_input` | `max_tool_rounds_stops_loop` |
| `SessionConfig.default_command_timeout_ms` | Supported as the shell default; an explicit valid tool-call `timeout_ms` wins. | `AgentSession::execute_tool_calls` → `ShellTool::execute_with_options` | `shell_tool_uses_session_default_command_timeout` |
| `SessionConfig.enable_loop_detection` | Supported. | `AgentSession::execute_tool_calls` → `LoopDetector` | `repeated_tool_calls_inject_one_loop_steering_turn` |
| `SessionConfig.loop_detection_window` | Supported; zero is safe and never triggers. | `AgentSession::execute_tool_calls` → `LoopDetector::record_and_check` | `repeated_tool_calls_inject_one_loop_steering_turn`, `zero_loop_detection_window_is_safe_and_never_injects_steering` |
| Provider `supports_streaming` | Supported as a truthful capability flag. All built-in streams are currently empty, so all built-ins return false; the positive mock returns a real event when it claims support. | `ProviderAdapter` implementations | `builtin_provider_streaming_claims_match_their_empty_streams`, `streaming_capability_fixture_yields_a_real_event` |
| `allowed_tools` / node `max_budget_usd` | Supported as strings only on Claude-backed codergen nodes. Malformed values and use everywhere else are rejected. | `ExecutionPlan` provider/handler gating → Claude command builder | `recognized_unsupported_execution_capabilities_fail_closed`, `claude_controls_are_rejected_for_non_codergen_handlers`, `claude_execution_controls_require_string_values`, Claude command-builder tests |
| `fidelity`, `reasoning_effort`, `auto_status`, `allow_partial`, `thread_id` | Rejected with `unsupported_execution_capability`; these fields have no canonical execution semantics. | `ExecutionPlan` fail-closed validation | `recognized_unsupported_execution_capabilities_fail_closed`, `stylesheet_reasoning_effort_is_rejected_instead_of_ignored`, `unsupported_capability_invokes_no_handler_event_or_checkpoint` |
| Fidelity and subagents | Removed: agent/types fidelity APIs and subagent bookkeeping. No shipped API claims compaction, summarization, or child-agent spawning. | None | Documentation/API absence contracts |
| Manager loops | Rejected: manager-loop roles in canonical non-web compilation. Raw handler symbols remain only for the separate web compatibility boundary. | `ExecutionPlan` fail-closed validation | `recognized_unsupported_execution_capabilities_fail_closed` |
| Multi-edge parallel / fan-in | Rejected with `unsupported_execution_topology`; zero/one-edge parallel remains sequential compatibility. | `ExecutionPlan::validate_supported_execution_topology` | `unsupported_topology_diagnostics_are_complete_and_deterministic` |

Goal-gate retry edges are graph traversal, not handler retries. They begin a new non-terminal node visit with a fresh node retry budget. Terminal retry targets are rejected, and `max_steps` remains the global execution safety bound.
